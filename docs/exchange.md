## 米游社商品兑换

米游社商品兑换功能支持使用米游币自动兑换商品，包括定时兑换和实时兑换两种模式。

### 功能特点

- **商品浏览**：支持按游戏分区浏览可兑换商品列表
- **实时状态**：显示商品库存、兑换时间、限购情况等实时信息
- **定时兑换**：支持设置兑换计划，到点自动兑换
- **重试机制**：抢到就停，没抢到就在设定时间内继续抢（可配置）
- **多账号支持**：每个账号可配置独立的兑换计划

### 自动兑换是怎么回事

简单说：**到开卖那一刻，它会替你连着按"兑换"按钮，抢到就停，一直没抢到就坚持到你设定的秒数用完为止。**

关键是两个设置（网页「自动兑换」面板里也能改）：

| 设置 | 人话解释 |
| --- | --- |
| `retry_seconds`<br>（网页：最多抢几秒） | 开卖瞬间开始，**最多坚持多少秒**。抢到就提前结束；时间一到无论成败都停手。`0` = 只发一次请求，不重试。 |
| `retry_interval`<br>（网页：最多隔几秒发一次） | 两次请求之间**最多隔多久**。实际是在 **0 ~ 这个数之间随机**（填 `0.3` 就是 0~0.3 秒随机），加随机是为了别让节奏太机械。最小 0.05 秒 —— 填 `0` 会被纠正成 0.05，不会真的不等待。 |

网页上会根据你填的数字实时估算大概发几次请求，例如「最多抢 5.5 秒 / 最多隔 0.3 秒」≈ 16 次（最少 11 次、最多 27 次）。

哪些行为是安全的（不会重复下单）：

- **同一条计划的「商品 + 开卖时间」只会自动抢一次**，失败也不会自动再来一轮（想重来就把计划的开卖时间改一下，或手动点商品卡上的「兑换」）。
- **同一账号 UID + 商品 + 开卖时间的重复计划，只执行排在最前面的启用自动计划**；不同账号可以分别执行。
- **同一条已保存计划的手动与自动兑换互斥**，正在执行时不能再次提交。商品卡直兑是独立操作，请避免对同一商品重复点击。
- **抢到之后计划会自动关闭**，旧页面保存不会撤销这次关闭。若确实要再次启用，先刷新读取兑换结果，再核对账号、时间并启用保存。
- 「启用商品自动兑换」这个开关**只管到点自动那条路**；商品卡上的「兑换」按钮不受它影响，手动随时能用。

### 兑换配置

在 `config.yaml` 中配置商品兑换功能：

```yaml
shop_exchange:
  enable: true          # 是否开启"到点自动抢"（关着也能手动兑换）
  retry_seconds: 20     # 到点后最多抢几秒（0 = 只发一次）
  retry_interval: 0.4   # 每两次之间最多隔几秒（实际在 0~这个数 之间随机；最小 0.05）
  push: true            # 兑换结束后是否推送结果
  plans: []             # 兑换计划列表
```

### 兑换计划配置

每个兑换计划包含以下字段：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `plan_id` | 计划的稳定 ID，由系统生成；重排时保持不变，不要在多条计划之间复用 | "example-plan-a" |
| `plan_version` | 执行版本，由系统维护；修改账号、地址、角色、时间或启用状态等执行字段时更新 | 系统自动生成 |
| `completion_token` | 成功状态标识，由系统维护；防止旧页面保存时重新启用已完成计划，无需手工填写 | 系统自动生成 |
| `goods_id` | 商品 ID | "12345" |
| `goods_name` | 商品名称（可选，用于显示） | "原神礼包" |
| `account_uid` | 执行账号的米游社 UID，必须唯一对应 `accounts[].stuid`，且账号已登录；不是游戏角色 UID | "100000001" |
| `account_index` | 账号在 `accounts` 中的位置，仅用于显示；重排后由 UID 重新计算，不作为下单身份 | 0 |
| `needs_account_confirmation` | 缺少账号 UID 的旧计划会标记为待确认并暂停，重新选择账号并保存后解除 | false |
| `address_id` | 收货地址 ID（实物商品必需） | "67890" |
| `uid` | 游戏角色 UID（游戏内商品必需，与 `account_uid` 含义不同） | "123456789" |
| `region` | 游戏区服（游戏内商品必需） | "cn_gf01" |
| `game_biz` | 游戏业务标识（游戏内商品必需） | "hk4e_cn" |
| `exchange_at` | 兑换时间戳（秒），请按实际开卖时间设置 | 1893456000 |
| `enable` | 是否启用该计划 | true |
| `auto` | 是否自动执行 | true |
| `device_fp` | 设备指纹（自动获取） | "xxx" |

配置结构示例（示例账号、商品、地址和时间都需要替换，确认前保持关闭；推荐通过网页添加计划，由系统生成 ID 和版本）：

```yaml
shop_exchange:
  enable: false
  retry_seconds: 20
  retry_interval: 0.4
  plans:
    - plan_id: "example-plan-a"
      account_uid: "100000001"  # 必须对应 accounts 中唯一的 stuid
      goods_id: "12345"
      goods_name: "示例实物商品"
      account_index: 0
      address_id: "67890"
      exchange_at: 1893456000  # 仅为时间戳示例，请替换为实际开卖时间
      enable: false
      auto: true
      device_fp: ""
```

### 使用方式

#### Web 控制台操作

1. **商品浏览**：在 Web 控制台切到「兑换」页
2. **选择商品**：浏览商品列表，选择要兑换的商品
3. **查看详情**：点击商品查看详细信息，包括库存、兑换时间等
4. **添加计划**：点商品卡上的「计划」按钮加入兑换计划，填好执行账号和开卖时间
5. **设置时间**：设置兑换时间（支持定时兑换）
6. **立即兑换**：商品卡上的「兑换」按钮，随时可以手动兑换（不受「自动兑换」开关影响）

已保存计划上的「立即兑换」会先保存当前编辑，再按计划 ID 和服务器确认的版本执行；若计划在此期间又被修改，需要重新保存后再试。

#### 旧计划升级与账号变更

只有 `account_index`、没有 `account_uid` 的旧计划会自动暂停，并显示「请重新选择并确认账号」。程序不会根据旧下标猜测原来的执行账号。

1. 在计划的「执行账号」中重新选择已登录账号。
2. 重新确认该账号的游戏角色或收货地址。改绑账号时旧角色、旧地址会清空。
3. 核对商品和开卖时间，再启用计划并保存。

账号重排不会改变已有 UID 绑定；删除账号、UID 重复或凭证缺失时，兑换会被拒绝，不会自动改用其他账号。无法确定原账号时，请先重新登录再绑定。

添加计划和商品直兑的账号选择也按 UID 绑定；等待登录检查、角色或商品接口期间删除账号，会拒绝继续执行。收货地址加载失败或旧地址已失效时会保留原地址 ID 供核对，不会因重绘自动清空；失效地址仍需重新选择。

每次执行使用开始时冻结的账号、计划和配置。执行中删除或实质修改计划，已经发出的请求仍可能完成，但旧结果不会写入修改后的计划，也不会误停用其他计划；单纯重排会按原计划 ID 记录结果。推送中的账号名也取自执行快照。

#### 商品类型说明

- **实物商品**：需要填写收货地址
- **游戏内商品**：需要填写游戏 UID、区服信息
- **通用商品**：可能不需要额外信息

### 兑换流程

1. **自动获取 device_fp**：系统会自动获取设备指纹
2. **时间校准**：定时兑换前会自动校准服务器时间
3. **精确等待**：兑换前 180 秒进入精确等待模式
4. **重试机制**：在配置的重试时长内持续尝试兑换
5. **结果通知**：兑换完成后通过配置的推送渠道通知

### 兑换注意事项

- 兑换功能需要账号已登录且凭证有效
- 实物商品需要提前在米游社配置收货地址
- 游戏内商品需要确保角色信息正确
- 定时兑换时间建议设置在商品上架时间点
- 重试时长和间隔可根据网络情况调整
- 兑换结果会记录在日志中，失败会显示原因

### 常见问题

**Q: 如何获取商品 ID？**  
A: 界面只显示商品名称，不显示 ID。`goods_id` 在 `config.yaml` 的 `shop_exchange.plans[].goods_id` 里，或者从接口返回的数据里看。用网页上的「计划」按钮加计划就不需要手填。

**Q: 如何获取收货地址 ID？**  
A: 在 Web 控制台添加兑换计划时，会自动加载账号的收货地址列表。

**Q: 游戏内商品的 UID 和区服如何填写？**  
A: 在 Web 控制台添加兑换计划时，会自动加载账号的角色信息。

**Q: 兑换失败怎么办？**  
A: 检查日志中的错误信息，常见原因包括：库存不足、时间未到、账号信息错误等。

**Q: 可以同时添加多个兑换计划吗？**  
A: 可以，每个账号可以添加多个兑换计划，系统会按时间顺序执行。

## 米游币任务

米游币任务默认关闭，需要时手动开启。

**目前实际可执行的只有「社区签到」**：看帖 / 点赞 / 分享在米游社改版后已经作废，程序里会强制按关闭处理（网页上那三个勾选框是灰的，勾了也不算数）。

米游币任务比游戏社区签到更容易遇到验证码或风控。第一次使用建议先只开启游戏社区签到，确认稳定后再开启米游币任务。
